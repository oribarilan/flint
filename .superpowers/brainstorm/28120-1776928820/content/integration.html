Copilot SDK + Work IQ Integration

How the pieces connect in Electron main process

Initialization Flow
// ── Electron main process (main.ts) ──
 
// 1. Create client (bundles + manages CLI binary automatically)
const client = new CopilotClient({
  cliPath: path.join(app.isPackaged ? process.resourcesPath : __dirname, "copilot"),
});
 
// 2. Create session with Work IQ MCP + custom tools
const session = await client.createSession({
  model: "gpt-4.1",
  streaming: true,
  systemMessage: {
    content: "You are Flint, a personal work assistant. Help the user
             manage their calendar, meetings, and work communications.
             Be concise and actionable.",
  },
  mcpServers: {
    "work-iq": {
      type: "local",
      command: "npx",
      args: ["-y", "@microsoft/workiq", "mcp"],
      tools: ["*"],
    },
  },
  tools: [showNotification, joinMeeting], // custom Electron tools
});
 
// 3. Stream responses to renderer via IPC
session.on("assistant.message_delta", (event) => {
  overlayWindow.webContents.send("chat:delta", event.data.deltaContent);
});
Data Flow: User Query → Response
1
Renderer → ipcRenderer.send("chat:send", "What meetings do I have tomorrow?")
2
Main → session.sendAndWait({ prompt }) — SDK sends to Copilot CLI via JSON-RPC
3
Copilot CLI → Agent decides to call Work IQ MCP tool ask_work_iq
4
Work IQ → Queries M365 Copilot Chat API → returns meeting data as structured response
5
Copilot CLI → Agent formats meeting data into natural language response, streams back
6
Main → Receives streaming deltas → forwards via ipcMain to renderer
7
Renderer → React state updates → streaming text renders in chat panel

Key Integration Details

Work IQ as Local MCP

Work IQ runs as a stdio MCP server via npx @microsoft/workiq mcp. The SDK spawns it as a child process alongside the Copilot CLI. No separate setup — just declare it in the session config. Auth uses the user's signed-in M365 credentials.

Session Persistence

SDK supports named sessions (sessionId: "flint-main") that persist to ~/.copilot/session-state/. Conversations survive app restarts. The meeting monitor can share session context with the user's chat — or use a separate background session.

Custom Tools (Electron actions)

Register Electron actions as Copilot tools: showNotification, joinMeeting (opens URL), showOverlay. The agent can autonomously trigger these — e.g., "remind me 5 minutes before" → agent calls showNotification tool with a timer.

Auth Model

Two auth chains: (1) GitHub Copilot — CLI handles auth via system keychain, user signs in once. (2) M365/Work IQ — Work IQ CLI handles M365 OAuth, user signs in once via workiq accept-eula. Both persist across restarts.
