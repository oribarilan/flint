# Sprint02-5: CI Signal & Runtime Optimization

## Summary

This ticket tightens CI so failures are faster to interpret and runtime stays bounded as checks expand. It preserves the existing `just check` baseline while improving focused-suite ergonomics (especially simulator/E2E paths) and actionable diagnostics.

## Requirements

- Keep current cross-platform baseline (`just check`) intact.
- Ensure focused suites are explicit and scoped (avoid accidental broad E2E runs).
- Improve failure signal quality (clear step names, artifacts/logs when useful).
- Prevent CI runtime creep from new sprint checks.

## Implementation

### Scope

1. Review and tighten `check.yml` job structure for clarity and bounded runtime.
2. Ensure simulator chat regressions run as focused specs only.
3. Add failure diagnostics where high-value (Playwright traces/screenshots on failure).
4. Document expected runtime budget and guardrails.

### Proposed Changes

- Keep existing matrix `check` job unchanged unless optimization is low-risk.
- Keep/add focused E2E job using explicit spec path and grep tag/title filter.
- Ensure Linux Playwright execution remains wrapped with `xvfb-run -a`.
- Add/verify artifact upload for failed E2E runs (trace/video/screenshots) via `actions/upload-artifact` and Playwright output directory.
- Document local reproduction command in task notes or docs.

- Runtime budget guardrail:
  - Define a target budget for the focused E2E job (e.g., ≤ 8 minutes on ubuntu-latest) and track drift in PRs.

### Runtime Budget (Initial)

- Focused simulator regression job target: **≤ 8 minutes** on `ubuntu-latest`.
- If exceeded on representative PRs, require either:
  - narrowing scope further, or
  - explicit follow-up optimization task.
